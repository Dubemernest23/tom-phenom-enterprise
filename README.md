# TOM-PHENOM ENTERPRISE

Internal operations tool for a sachet water production and distribution
business. A single-page app for one person's daily record-keeping, built
for fast, one-handed use on a phone.

It tracks raw material intake, packing bag inventory, the daily production
log, distribution to two delivery channels (keke and van), a customer
credit ledger, worker payroll, equipment maintenance, and money owed to
suppliers/vendors.

## Feature overview

| Module | What it does |
|---|---|
| Dashboard (`#/dashboard`) | Landing page. Today's production, "Owed to us" vs "We owe" KPIs, monthly roll kg, packing bags remaining, quick actions |
| Roll Intake (`#/roll-intake`) | Record rolls received: quantity, kg, price/kg, amount paid; shows computed total price and balance |
| Packing Bags (`#/packing-bags`) | Batch-level bag stock — add a batch, draw down bags per batch |
| Daily Factory Log (`#/factory-log`) | Opening/closing stock, distribution & in-house quantities, computed production |
| Distribution (`#/distribution`) | Give bags to keke/van drivers; records expected amount and running balance |
| Customers (`#/customers`) | Customer credit ledger with running balances; add transactions against a customer |
| Payroll (`#/payroll`) | Workers, base salaries, and per-period salary records (salary due, advance, paid, balance) |
| Maintenance (`#/maintenance`) | Equipment repairs/costs with a current-month running total |
| Payables (`#/payables`) | Creditor/vendor ledger — money the business owes out, with balance per creditor |

## Tech stack

- **Frontend:** plain JavaScript (ES modules) — no React/Vue, no bundler.
  One `index.html`, hash-based routing (`#/dashboard`, `#/customers/:id`).
- **Styling:** Tailwind CSS configured to this project's own design tokens
  (the default Tailwind palette and fonts are not used).
- **Backend (planned):** Express + MySQL API, built separately.
- **Deployments:** Render Static Site + Render Web Service (see
  `docs/monorepo-structure.md`).

## Prerequisites

- **Node.js 16+** (any recent LTS is fine) and npm.
- You do **not** need any JS build tooling beyond npm — there is no bundler.

## Getting started

Clone the repo, then everything happens inside `apps/frontend`:

```sh
git clone <this repo>
cd apps/frontend
npm install
```

### Quick start

```sh
npm run build      # compile Tailwind into src/styles/output.css
npm run preview    # serve the app at http://localhost:5173
```

Open http://localhost:5173. The frontend runs entirely as static files —
no Node server is required at runtime.

### Day-to-day development

Run two terminals from `apps/frontend`:

```sh
# Terminal 1 — rebuild CSS on every change
npm run dev

# Terminal 2 — static file server
npm run preview
```

The app is an SPA: as you build the pages, navigation between modules
happens through hash routes with no full page reloads.

## npm scripts

| Script | Command | Purpose |
|---|---|---|
| `build` | `npx tailwindcss -i ./src/styles/tailwind.css -o ./src/styles/output.css --minify` | One-off minified CSS build. Run before preview/deploy if `output.css` is missing. |
| `dev` | same as build, with `--watch` | Continuous rebuild while editing markup/JS |
| `preview` | `serve . -l 5173` | Local static server for `apps/frontend` |

## Connecting the frontend to the API

All API calls go through `src/api.js`, which imports the base URL from
`src/config.js`. That file currently contains:

```js
export const API_BASE_URL = 'http://localhost:4000/api';
```

- **Locally:** point this at your running backend and edit `src/config.js`
  by hand.
- **On Render:** `API_BASE_URL` is injected at build time. The Static Site's
  build command regenerates `src/config.js` from an `API_BASE_URL` env var,
  so no real value is committed. Details in `docs/monorepo-structure.md`.

> The backend (`apps/server`) is not built yet. Until it exists, the
> frontend renders the design-system shell and splash screen; pages that
> load data need the API.

## Styling and design tokens

The app's look is defined in `docs/FE-system-design.md` — treat it as law.
Key points:

- Colors, fonts, and type scale live in `src/styles/tokens.css` as CSS
  custom properties, and again as named values in `tailwind.config.js`
  (which references the variables — one source of truth).
- Use theme utility classes (`bg-primary`, `text-ink-muted`, `font-heading`)
  — not Tailwind's default palette and not one-off hex values.
- Two fonts are loaded from Google Fonts: **Space Grotesk** (headings) and
  **Inter** (body/UI). Loading these needs internet access; without it the
  app falls back to system sans-serif.

## Deployment (Render)

The plan (documented in full in `docs/monorepo-structure.md`) is two Render
services plus an external managed MySQL database:

1. **Frontend — Render Static Site** pointing at `apps/frontend`. Build:
   `npm install && npx tailwindcss -i ./src/styles/tailwind.css -o ./src/styles/output.css --minify && echo "export const API_BASE_URL = '$API_BASE_URL';" > src/config.js`
2. **Backend — Render Web Service** (once built) with `DATABASE_URL` and
   `CORS_ORIGIN` env vars.

A `render.yaml` Blueprint standing up both services together is planned at
the repo root (per the architecture doc); it isn't written yet. Env vars are
set in the Render dashboard, never committed.

## Troubleshooting

| Problem | Fix |
|---|---|
| Blank page / no styles | `output.css` is generated and git-ignored. Run `npm run build` first. |
| `EADDRINUSE :5173` | Port in use — edit the `preview` script port in `package.json`. |
| Fonts look wrong | Confirm internet access for the Google Fonts `<link>` in `index.html`. |
| API calls fail | Check `API_BASE_URL` in `src/config.js` matches your backend; confirm CORS on the backend allows the origin. |
| Deep link returns 404 on some hosts | Hash routing (`#/…`) avoids this on any static host, including plain GitHub Pages. |
